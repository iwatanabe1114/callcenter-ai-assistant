# コールセンターAIアシスタント

社内マニュアルや過去の対応履歴をAIが検索して答える、コールセンター向けの社内ツールです。
設計書「コールセンターAIアシスタント_設計書_初心者向け.pdf」の内容をそのまま実装しています。

- 資料の置き場所：**Google スプレッドシート**
- 検索：**キーワード検索（日本語向け bi-gram BM25）**。追加のAI費用なし
- 回答生成：**Claude Opus 5**／クエリ拡張：**Claude Haiku 4.5**（速くて安い軽量AI）
- 画面：**Streamlit**（画面と処理を1つにまとめて作れる）

---

## 1. できること（画面）

| 画面 | ファイル | ログイン | 内容 |
|---|---|---|---|
| チャット | `app.py` | 任意（共有パスワード） | 質問すると資料を探してAIが答える。出典リンク付き |
| 管理画面 | `pages/1_⚙️_管理画面.py` | **必須** | 資料の再取得・利用状況の集計・個人情報の点検 |

資料の修正はスプレッドシート側で行います。**このアプリはスプレッドシートを読むだけ**で、
書き込みは一切しません（Googleの権限も読み取り専用に設定しています）。

## 2. 動かしてみる（設定なしでOK）

```bash
cd ~/callcenter-ai-assistant
.venv/bin/streamlit run app.py
```

初期状態では `data/sample/` のサンプルデータで動きます。
APIキーが未設定のあいだは「検索まで」動き、AIの回答生成だけが止まります。

セットアップからやり直す場合：

```bash
python3 -m venv .venv && .venv/bin/pip install -r requirements.txt
```

## 3. 本番用のセットアップ

### 3-1. 設定ファイルを作る

```bash
cp .streamlit/secrets.toml.example .streamlit/secrets.toml
```

`.streamlit/secrets.toml` を編集します。**このファイルは `.gitignore` 済みで、コード管理には入りません**（設計書5.3）。
Streamlit Community Cloud にデプロイする場合は、この中身をアプリ設定の「Secrets」欄に貼り付けます。

必ず埋めるもの：

| 項目 | 内容 | 入れ方 |
|---|---|---|
| `anthropic_api_key` | Claude API のキー | `python -m batch.setup_llm` |
| `[passwords]` の `admin` | 管理画面のパスワード。**必ず変更する** | 手で編集 |
| `[gcp_service_account]` | Google サービスアカウントのJSONの中身 | `python -m batch.setup_sheets <鍵.json>` |
| `[[sources]]` | ジャンルごとの スプレッドシートID・シート名・**読み込む列** | 同上（一緒に入ります） |
| `[tenant]` | ブランドの識別番号（複数ブランドを扱う場合は必ず設定） | 手で編集 |

### 3-1-b. Claude APIキーを入れる

APIキーはコマンドの引数に書きません（シェルの履歴に残るため）。
実行すると入力を求められるので、そこに貼り付けてください（画面には表示されません）。

```bash
.venv/bin/python -m batch.setup_llm
```

設定後、実際に呼び出して確認できます（費用は1円未満）。

```bash
.venv/bin/python -m batch.setup_llm --check
```

言い換え生成（Haiku）と回答生成（Opus）の両方を、アプリが実際に使う構造化出力の形で
呼び出して確認します。スプレッドシートを繋ぐ前でも、サンプルデータでAIの回答を試せます。

> 設定を変えたらアプリを再起動してください。設定値は起動時に一度だけ読み込まれます。

### 3-2. Google スプレッドシートを繋ぐ

**① サービスアカウントを作る**

1. [Google Cloud Console](https://console.cloud.google.com) でプロジェクトを選ぶ（無ければ新規作成）
2. 「APIとサービス」→ ライブラリ →「**Google Sheets API**」を有効にする
3. 「APIとサービス」→ 認証情報 →「認証情報を作成」→「**サービスアカウント**」
4. 作ったサービスアカウントを開く →「キー」タブ →「鍵を追加」→「**JSON**」

**② 鍵を設定ファイルに取り込む**

ダウンロードしたJSONを、そのままこのコマンドに渡してください。
`private_key` の改行の扱いなど、手で書き写すと失敗しやすい部分を自動で処理します。
取得元シート13枚の設定も一緒に入ります。

```bash
.venv/bin/python -m batch.setup_sheets ~/Downloads/xxxxx-abc123.json
```

実行すると、共有先のメールアドレス（`〜@〜.iam.gserviceaccount.com`）が表示されます。

**③ スプレッドシートを共有する**

表示されたメールアドレスを、スプレッドシートの「共有」に **「閲覧者」** で追加します
（このアプリは読むだけなので、編集者権限は不要です）。

**④ 繋がるか確認する**

```bash
.venv/bin/python -m batch.setup_sheets --check
```

13シートを1枚ずつ開いて行数を表示します。共有漏れやシート名の間違いは、
ここで「共有されていません」「シート名が違います」として表示されます。

### 3-2-b. 実際のシート用の設定は用意済みです

対象スプレッドシート（ファイルID `1rKl3y3zVi…`）の13シート分の設定を
`.streamlit/sources.example.toml` に書いてあります。
共有設定の見直しが済んだら、この中身を `.streamlit/secrets.toml` の末尾に貼り付けてください。

| ジャンル | シート | 備考 |
|---|---|---|
| マニュアル | 回覧板 / PBX音声ガイダンス | 回覧板は共有日から180日を過ぎた行を除外 |
| キャンペーン・施策 | 施策シートリンク / 新規ポイントスケジュール | 終了日から180日を過ぎた行を除外 |
| 料金 | 全商材価格表 | 列名が重複するため列位置で指定・商材名は上の行から引き継ぎ |
| 商品 | 商材8シート | 縦持ち（A列＝項目名）として読み込み |

**読み込まないシート**（意図的に設定していません）：

- `メール配信リスト` … お客様のメールアドレス
- `カルテ項目` … 家族構成・お仕事などの個人情報テンプレート
- `IDPASS（クレカ）` … 現在は中身が空のため対象外

> ⚠️ サービスアカウントには**ファイル単位**で権限が付きます。設定しなかったシートも
> サービスアカウントからは読める状態になります。将来 `IDPASS（クレカ）` に実際の
> 認証情報を入れる場合は、そのときに別ファイルへ移してください。

### 3-3. 読み込む列を決める（重要・設計書5.2）

`[[sources]]` の `columns` に書いた列**だけ**を読み込みます。

```toml
[[sources]]
genre = "manual"
spreadsheet_id = "1AbCdEf..."
worksheet = "マニュアル"
columns = ["タイトル", "本文", "カテゴリ", "更新日"]   # ← ここに書いた列だけ
title_columns = ["タイトル"]
body_columns = ["本文", "カテゴリ"]
```

**お客様の氏名・電話番号がそのまま入っている列は、ここに書かないでください。**
書かなければアプリ側に一切入ってきません。これが一番安全な作り方です。

ジャンルは4種類です。1つのジャンルに複数のシートを割り当てられます（取り込み時に統合されます）。

| genre | 用途 |
|---|---|
| `campaign` | キャンペーン・施策 |
| `manual` | マニュアル |
| `price` | 料金表 |
| `product` | 商品リスト |

### 3-3-b. シートの形を指定する

| `layout` | 形 | 例 |
|---|---|---|
| `table`（既定） | 1行目が列名・1行が1件 | 回覧板、施策シートリンク |
| `key_value` | A列に項目名・右の列に内容（縦持ち） | 商材シート |

`table` で使えるオプション：

| 設定 | 効果 |
|---|---|
| `columns` | 列名（`"共有日"`）でも列位置（`"A"` `"AB"`）でも指定できる。同じ列名が複数あるシートは位置で指定する |
| `column_labels` | 位置で指定した列に表示名を付ける |
| `header_row` | 列名が何行目にあるか（上に説明文があるシート用） |
| `fill_down_columns` | セル結合で空になっている列を、上の行の値で埋める |
| `date_column` + `max_age_days` | 指定日数より古い行を取り込まない。**日付が空・読み取れない行は除外しません**（消しすぎないため） |

`key_value` で使えるオプション：

| 設定 | 効果 |
|---|---|
| `key_column` | 項目名が入っている列（既定 `"A"`） |
| `value_columns` | 内容が入っている列の候補。左から見て最初に値があるものを使う（商材によりB列/C列が混在するため） |
| `start_row` | 何行目から読むか。商材シートは1行目がバナーなので `2` |
| `skip_keys` | 読み飛ばす項目名（画像欄など） |

### 3-4. 資料を取ってくる

```bash
.venv/bin/python -m batch.ingest          # 全ジャンル
.venv/bin/python -m batch.ingest manual   # ジャンル指定
```

自動実行（毎日5時）の例：

```bash
0 5 * * * cd /Users/watanabeibuki/callcenter-ai-assistant && .venv/bin/python -m batch.ingest >> data/logs/ingest.log 2>&1
```

**この処理はアプリ本体とは別のプログラムです。**
アプリの中に混ぜると、オペレーターが質問している最中に重い処理が走って
画面が遅くなります（設計書2.3・4.1）。
急いで反映したいときだけ、管理画面の「今すぐ資料を取り直す」を使ってください。

### 設計書から外した機能

運用方針の判断により、次の2つは実装していません。

| 設計書 | 機能 | 外した理由 |
|---|---|---|
| 3.3 | 本社確認判断 | 根拠②にあたる過去の対応履歴データが無く、機能として成立しないため |
| 3.1 | 音声入力 | 使わないため。Gemini APIキーの管理も不要になります |
| 3.4 | ナレッジ編集 | 使わないため。資料の修正はスプレッドシート側で行います |

いずれも独立した部品だったので、削除してもチャット画面・管理画面には影響しません。

ナレッジ編集を外したことで、アプリは**スプレッドシートを読むだけ**になりました。
そのため Google の権限も `spreadsheets.readonly`（読み取り専用）に絞ってあります。
万一アプリ側に不具合があっても、元のシートを書き換えることはできません。

### とくに気をつけている3点

**① AIの回答が途中で切れたら、結果を捨てる（4.4）**
構造化出力は、長さの上限に達すると「一見正常に見えるデータ」として返ってきます。
`stop_reason` を必ず確認し、`max_tokens` だった場合は結果を使わず安全な表示に切り替えます。
本社確認判断では、判断できない場合は必ず「本社に確認が必要」（安全側）に倒します。

**② 参照元はAIに書かせない（8.3）**
「何行目・どの資料か」はAIに作文させると間違えます。
検索結果があらかじめ持っている `source_label` / `source_url` を、画面側が機械的に表示します。

**③ 追加した検索語は重みを下げる（4.3）**
AIが追加した言い換え語を元の質問と同じ重みで扱うと、一般的すぎる語が
全部の資料にヒットして精度が落ちます。既定では 1.0 と 0.35 に分けています。
さらに、日本語の言い回し由来の語（「した」「たい」など、ひらがなだけの2文字）も
軽く扱うようにしています。

## 5. デプロイ（Streamlit Community Cloud）

1. このフォルダを GitHub のリポジトリに push する（`.gitignore` により秘密情報は入りません）
2. Streamlit Community Cloud でリポジトリを指定し、メインファイルを `app.py` にする
3. アプリ設定の **Secrets** に `.streamlit/secrets.toml` の中身を貼り付ける
4. デプロイ後、管理画面から「今すぐ資料を取り直す」を1回実行する

バッチ処理は Streamlit Cloud 上では動かないので、GitHub Actions か社内サーバーの
cron で `python -m batch.ingest` を定期実行し、その結果をコミットするか、
管理画面から手動で取り直してください。

**本番に反映するときは、小さい単位に分けて行ってください**（設計書5.5）。
何か問題が起きたときに、すぐ元に戻せるようにするためです。
コードの共同管理では、履歴を書き換えない「マージ」を基本にしてください（8.4）。

## 6. いまの制約・あとから足せること

- **意味で探す検索（ベクトル検索）は未実装**です。キーワード検索のみで開始しています。
  過去の対応事例のように言い回しがバラバラなデータでは、これが効いてくる場面があります。
  足す場合は `core/search.py` のスコア計算と `core/retrieval.py` に埋め込み検索を並べ、
  結果を混ぜる形になります。クラウド上でちゃんと動くか、事前に必ず確認してください（設計書7）。
- **検索は「関連しそうな資料をAIに渡す」ところまでが役割**です。
  1位が必ずしも最適とは限らないため、既定で上位6件をまとめてAIに渡しています。
- **マスキングは完璧ではありません**。一番の防御はログイン制限と「使う列だけ読む」ことで、
  マスキングはその上に重ねるもう1つの安全策です。管理画面の「個人情報の点検」で
  定期的に取りこぼしを確認してください。
- **本社確認判断・音声入力は実装していません**（上記「設計書から外した機能」）。
